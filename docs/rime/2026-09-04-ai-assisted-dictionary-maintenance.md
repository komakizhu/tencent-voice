# Rime 个人词库可视化维护与 AI 审核设计记录

## 文档状态

本文档是已确认需求和后续实施边界的记录。本次只写入工作区文档，不修改代码、`~/Library/Rime`、共享同步数据或已安装应用。

## 任务重新定义

Rime 的 `rime_ice.userdb` 继续负责日常自学习和动态排序。新模块不再试图把全部用户库转换为人工勾选词库，而是做三件事：

1. 在 `mac` 与 `mac2` 之间交换快照，但不让两个 Squirrel 进程共用实时 userdb。
2. 可视化发现并清理错词、误选词和无意义组合。
3. 从近期学习中提炼人名、项目名和专有词，纳入独立的长期记忆词库。

腾讯语音、腾讯云热词、Ollama、DeepSeek 和网络热词不属于本支线。

## Rime 数据的解释边界

快照中的 `c`、`d`、`t` 应保留原始值：

- `c` 表示累计提交次数，适合作为可解释的筛选条件，但不能单独判定一个词是否值得保留。
- `d` 是 Rime 保存的衰减/动态强度数据，需与当前逻辑时钟一起解释。
- `t` 是逻辑时钟，不是 Unix 时间，不能直接转换成“上周”或“上个月”。

“有效热度”必须在实施前用当前 librime 版本的行为和隔离样本验证，不自行发明一个看似精确但与 Rime 排序不一致的公式。界面可以用它排序和分组，不把它作为唯一删除门槛。

## 数据分层与排名语义

### 动态学习库

`rime_ice.userdb` 保留 Rime 的自学习数据，继续根据使用和衰减调整候选排名。AI 和人工审核不直接编造或重写 `c/d/t`。

### 长期记忆库

`rime_managed.dict.yaml` 只保证“这个词存在”，使用中性、低干预的基础权重。它不使用 `custom_phrase.txt` 的强制置顶语义，也不把历史 `c` 简单复制为静态高权重。词条后续的合理位置仍由 Rime 的 userdb 动态学习决定。

### 审核状态库

独立记录已处理快照、审核决策、首次发现时间、最后变化时间、本次跳过和永久忽略。不把这些数据写入 `custom_phrase.txt`。

## 审核动作

每个词条可以产生以下互斥决策：

| 动作 | 效果 |
| --- | --- |
| 保留动态学习 | 保留在 userdb，不写入长期记忆库 |
| 加入长期记忆 | 写入 `rime_managed.dict.yaml`，不强制置顶 |
| 删除错误学习 | 从当前账户 userdb 的经过滤快照中移除，应用前备份 |
| 本次跳过 | 只不处理当前审核会话，下次仍可出现 |
| 永久忽略 | 移除当前的错误学习记录，并阻止它被另一账户快照再次导入 |
| 需要人工确认 | 不修改数据，保留在待处理列表 |

“永久忽略”只能阻止用户学习记录重新同步。如果同一词本来就在基础词典中，要从候选中完全屏蔽它，需要另外的冷词/过滤机制，不与本动作混为一谈。

## 噪音和陈旧记录规则

### 可确定的默认噪音

- 纯单个 ASCII 字母词条默认归入噪音并隐藏。这条规则不等于隐藏单个汉字。
- 解析层只把空词条、空编码、字段数不符、数值无法解析、包含制表符/换行符等结构破损记录定义为“无效”。

### 不自动判定的“异常编码”

不仅因为编码大写、少见、包含空格或不像常见全拼就删除。Rime 配置中存在英文、双拼和自定义转换，这些外观异常的编码仍可能合法。结构合法但语义可疑的记录只打上“需要 AI/人工确认”标记。

### 近期热度接近零

归入“疑似噪音”默认隐藏，但不自动删除。这样可以缩小列表，同时保留“只打过一次但很重要”的词被搜索、AI 推荐或人工恢复的可能。“接近零”的数值不预先写死，实施时根据真实快照的热度分布设定分位阈值，并在界面显示当前实际阈值。

### 陈旧记录

历史快照不能根据 `t` 准确还原日历时间。首次启用只能计算“当前逻辑时钟 - 词条 `t`”，标注为“逻辑陈旧”，不自动删除。管理器开始观测后，用自己记录的 `firstSeenAt` 和 `lastChangedAt` 提供真实的近一周、近一月、近半年和近一年筛选。

## 可视化和筛选交互

首屏不再显示“4.7 万条全部勾选”。默认进入“建议处理”视图，优先显示新增/变化、不在基础词库、疑似错词、值得长期记住和 AI 无法确定的记录。“全部原始记录”仍可主动切换。

### 累计次数

使用五档滑块：

```text
全部 —— ≥3 —— ≥10 —— ≥30 —— ≥100
```

选择 `≥10` 时严格只显示 `c >= 10` 的记录。

### 有效热度

表格提供“有效热度”列，默认支持倒序排列；同时提供五档滑块作为二次筛选。因为热度通常不是线性分布，滑块按当前快照分位分档，每一档同时显示实际数值阈值，避免“一格”在不同快照中含义不同却无法解释。

### 最近使用

使用五档滑块：

```text
全部 —— 近一年 —— 近半年 —— 近一月 —— 近一周
```

它使用管理器自己观测到的 `lastChangedAt`。首次导入的历史词条无法凭空获得准确日期，界面必须显示“历史日期未知”，不伪造时间。

累计次数、热度、最近使用、列排序、视图和搜索条件都保存为当前账户的界面偏好。

## AI 表格导出与结果导入

### 导出

导出 `rime-audit.csv`，每行包含：

- 稳定 ID（由规范化后的词条与编码生成）。
- 词条、编码、原始 `c/d/t` 和计算后的有效热度。
- 来源账户、是否在基础词库、`firstSeenAt`、`lastChangedAt`。
- 快照摘要和导出批次 ID，防止 AI 的旧结果误用到新快照。

默认只导出当前过滤后的建议池。全量导出必须分批，避免 4.7 万条超出模型上下文。

### AI 返回结果

AI 只返回结构化决策，不改写原始数值：

```text
id,action,confidence,reason
```

`action` 只允许：

- `keep_dynamic`：保留动态学习。
- `promote_permanent`：加入长期记忆。
- `delete_learned`：删除错误学习。
- `ignore_permanent`：永久忽略并阻止再同步。
- `review_manually`：需要人工确认。

导入时先验证批次、快照摘要、ID、动作枚举和数据范围。然后显示汇总预览，例如“建议删除 320 条、长期记住 46 条、待人工确认 18 条”。只有在用户明确确认后，才创建备份、原子应用决策并重新部署；失败时恢复旧数据。

## 本地 MCP Server 路线

导出/导入是数据合同和可以始终使用的备用界面。在此合同之上，优先增加本地 MCP Server，让 Codex 不需要手动搬运 4.7 万条文本就能分批审核。MCP 和菜单栏窗口共用同一个核心协调器，不建立第二套词库逻辑。

首版 MCP 接口分为三层：

1. 只读：查看统计、按筛选条件分页读取词条、查看某个导出批次。
2. 提案：提交 AI 决策到待审核区，只生成预览，不改写 Rime。
3. 应用与恢复：在快照摘要未变、备份已建立且用户已明确确认时应用；按备份 ID 恢复。

预期工具语义：

```text
rime_audit_summary
rime_audit_list
rime_audit_export
rime_audit_submit_proposal
rime_audit_preview
rime_audit_apply
rime_audit_restore
```

`rime_audit_apply` 不接受自由文本指令，只应用已校验的提案。MCP Server 在本机运行并不等于词条一定不会离开本机；当 Codex 或其他云端模型读取 MCP 资源时，所读词条仍会进入模型上下文。未来需同时提供“只允许本地模型”和“允许指定批次交给云端模型”两种隐私模式。

## 双账户同步语义

- 当前账户只发布自己的快照，不直接写另一账户的实时 userdb。
- 机械同步层负责快照、受控词库和审核状态的可恢复交换。
- 审核层负责人工/AI 判断，不在同步时将远程快照无条件并入 userdb。
- 永久忽略记录与长期记忆词库都在两账户间同步；本次跳过只属于当前审核会话。

## 实施前的必要验证

1. 在真实快照的脱敏统计上查看 `c`、`d`、`t` 和计算热度的分布，再确定热度滑块的分位点和“接近零”阈值。
2. 用隔离 Rime 目录验证过滤快照的导出、恢复和重建语义，不在唯一的实时 userdb 上试验。
3. 验证长期记忆词库的中性权重不会把新词强制提到首选，且 userdb 仍能动态改变其排名。
4. 根据菜单栏应用当前的词库列表性能确定分页/虚拟表格方案，避免再次一次构建 4.7 万个复选控件。
5. 在实施 MCP 前先固定导入/导出 schema，使图形界面、CLI 和 MCP 共用相同的决策格式、验证和回滚路径。

## 后续验收标准

- 默认视图不再将全部原始词条当成待导入数据。
- 单个 ASCII 字母和近期热度接近零的记录默认隐藏，但不无备份自动删除。
- 累计次数、有效热度和最近使用都有可保存的滑块/排序设置。
- 本次跳过与永久忽略是两个独立动作。
- 长期记忆词只保证存在，不强制提到候选首位。
- AI 结果只能进入待确认提案，不能跳过预览、备份和回滚机制。
- `mac` 与 `mac2` 不直接共用实时 userdb，错词清理、永久忽略和长期记忆决策能在两账户间一致传播。
