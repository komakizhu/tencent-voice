# 腾讯实时语音输入 MVP 设计

日期：2026-09-03

状态：设计已由用户确认，等待规格复审

平台：仅 macOS

## 1. 目标

先做一个独立于鼠须管/Rime 的 macOS 菜单栏应用，让用户可以连续使用一周来判断腾讯实时 ASR 的实际效果。应用不提供预编辑区：腾讯返回的临时识别结果会直接写入当前光标位置，并随着后续结果到达而改写；松开快捷键后只保留一次最终结果。

本 MVP 的默认全局快捷键是 `F5`，并且必须可以在设置中替换。交互采用按住说话、松开结束。

## 2. 范围

包含：

- macOS 菜单栏应用，不依赖当前启用的输入法。
- 全局按键监听，默认 `F5`，支持功能键或带修饰键的安全组合键自定义。
- 麦克风采集、16 kHz 单声道 PCM 转换和腾讯实时语音识别 WebSocket 连接。
- 默认使用腾讯中英混合模型 `16k_zh_en_2.0`。
- 在常见可编辑文本控件中实时替换临时识别文本，并在结束时提交最终文本。
- 对不支持辅助功能文本读写的控件提供最终结果粘贴回退。
- 首次运行的麦克风、辅助功能权限引导。
- 腾讯凭证保存在 macOS Keychain；非敏感设置保存在本地用户设置中。
- 可选的本地文本识别日志，默认不保存音频。

不包含：

- 鼠须管/Rime 集成、Rime fork、词库学习和词频调整。
- Ollama、Qwen、本地模型后处理。
- 网络热词抓取、腾讯热词表、自学习定制模型。
- Windows 支持、语音命令、录音文件保存和云端录音管理。
- 独立的预编辑窗口、浮层或候选词界面。

## 3. 用户流程

首次启动时，菜单栏应用引导用户填写腾讯 AppID、SecretId、SecretKey，并跳转到系统设置授予麦克风和辅助功能权限。SecretId/SecretKey 只进入 Keychain，不写入配置文件、日志或错误信息。

用户在“设置”中可以：

- 查看和重新绑定全局快捷键；默认显示 `F5`。
- 修改识别引擎配置（初始值为 `16k_zh_en_2.0`，普通用户无需修改）。
- 开关本地文本日志。
- 查看当前权限、凭证和连接状态。

日常使用流程：

1. 在任意文本输入位置按住 `F5`。
2. 应用锁定当前焦点控件和光标位置，建立一次新的腾讯识别会话。
3. 麦克风音频通过 WebSocket 上传，临时结果直接出现在当前文本框中，并被后续临时结果替换。
4. 松开 `F5` 后停止采集，等待最后结果；最终结果替换最后一段临时文本，只提交一次。
5. 菜单栏图标回到空闲状态。

## 4. 架构

应用拆分为以下边界清晰的组件：

- `HotkeyManager`：注册、注销、重新绑定全局快捷键，输出 `keyDown`/`keyUp`，过滤按键重复事件。
- `SessionCoordinator`：管理一次按键会话的生命周期，串联音频、ASR 和文本写入，保证结束时只结算一次。
- `AudioCapture`：从默认输入设备采集音频，转换成 16 kHz、单声道、16-bit PCM 分片；连接建立前只保留短暂内存缓冲，不落盘。
- `TencentASRClient`：生成签名 WebSocket 地址，发送音频，接收腾讯事件，并把供应商协议转换为应用内部事件。
- `ASRResultNormalizer`：按供应商的结果序号和结束标志归并结果，区分 `partial` 与 `final`，防止同一段文字被重复追加。
- `TextInjector`：读取当前辅助功能文本控件的值和选区，维护自己拥有的临时文本范围，并执行安全替换。
- `SettingsStore`/`CredentialStore`：分别保存非敏感设置和 Keychain 凭证。
- `SessionLogger`：只在用户打开日志开关时记录文本结果、延迟和错误；不记录音频和密钥。

数据流：

```text
F5 down
  -> SessionCoordinator
  -> 焦点/光标快照 + TencentASRClient 建连
  -> AudioCapture -> WebSocket -> ASRResultNormalizer
  -> TextInjector（替换临时文本）
F5 up
  -> 停止采集 -> 等待 final -> TextInjector（一次性提交）
```

实现使用原生 Swift/AppKit、AVFoundation、ApplicationServices 和 Carbon 系统 API，MVP 不引入第三方运行时依赖。菜单栏应用使用原生状态栏项目，不抢占前台窗口。

## 5. 直接实时改写上屏

“实时改写”不是把每条识别结果继续拼接，而是维护一个明确的临时范围：

1. 会话开始时记录焦点控件、完整文本和选区；首个结果插入原选区。
2. 每个临时结果只替换上一次临时结果对应的范围。
3. 最终结果替换临时范围并转为已提交文本；之后的临时结果只能作用于新的临时范围。
4. 收到重复事件、旧序号事件或已经结算的事件时直接丢弃。

这里的“只提交一次”是指同一个结果序号/临时片段只结算一次。若腾讯把较长语音拆成多个有序的最终片段，各片段可以分别按序提交，但不会再次追加同一片段。

每次改写前都验证焦点控件仍是同一个、文本仍符合上一次由应用写入的投影、光标仍位于应用维护的范围之后。如果用户在说话期间手动输入、移动光标、切换窗口，应用立即停止对该控件进行实时覆盖，避免删改用户自己的文字。此时继续完成 ASR；如果无法安全定位插入点，只把最终结果放入剪贴板并通过菜单栏状态提示用户手动粘贴，不再盲目追加一份文本。

对于不支持 `AXValue`/`AXSelectedTextRange` 的输入控件，会在会话开始时进入“最终粘贴”模式：识别期间不反复发送临时文本，松开 `F5` 后只粘贴一次最终结果。这样仍然没有预编辑区，也不会因控件不兼容造成重复文本。

## 6. 腾讯实时 ASR 接入

`TencentASRClient` 以腾讯实时语音识别 WebSocket V2 为适配边界。每次会话生成新的 `voice_id`，使用本地凭证生成短期签名连接；连接中断后废弃旧的 `voice_id` 并在下一次按键时重新生成。默认参数为：

- `engine_model_type=16k_zh_en_2.0`
- `voice_format=1`（PCM）
- 16 kHz、单声道音频
- `needvad=0`，由 F5 的按下/松开控制会话边界
- 不传 `hotword_id` 和 `customization_id`

WebSocket 协议的供应商字段只在 `TencentASRClient` 内部处理，其他组件只接收统一事件：`connected`、`partial(text, sequence)`、`final(text, sequence)`、`ended`、`error(code, message)`。协议升级时只修改该适配器和对应测试。

连接未及时建立时，最多暂存约 1 秒的内存音频，连接成功后补发；超过上限则丢弃最早分片并在状态栏提示。松开快捷键后停止采集并发送结束信号，最多等待 2 秒接收最终结果；超时则使用最后一个安全结果或报告失败，不无限等待。

腾讯接口依据：

- [实时语音识别（WebSocket）API](https://cloud.tencent.com/document/api/1093/48982)
- [实时语音识别 V2（WebSocket）](https://cloud.tencent.com/document/product/1093/131127)
- [热词和自学习定制模型说明](https://cloud.tencent.com/document/product/1093/89081)

## 7. 快捷键设计

快捷键配置包含 macOS virtual key code 和 modifier flags 两部分，保存在用户设置中。默认值是无修饰的 `F5`。设置界面通过一次按键捕获获得新组合，并在注册成功后才替换当前快捷键；注册失败时保留旧快捷键并显示原因。

为避免吞掉正常文字输入，不允许把单个普通字母、数字或标点注册为全局快捷键；功能键以及带 `⌘`、`⌥`、`⌃`、`⇧` 的组合键可以使用。按住触发录音，松开结束；重复的 keyDown 不会重复创建会话。若硬件键盘把 F5 映射为系统功能，用户可在设置中绑定 `Fn+F5` 或其他组合键。

## 8. 权限、隐私和错误处理

- 缺少麦克风权限：不建立 ASR 会话，菜单栏给出系统设置入口。
- 缺少辅助功能权限：仍可尝试最终粘贴，但实时替换不可用；菜单栏明确显示权限状态。
- 凭证错误或签名过期：不向文本框写入错误信息，只显示可读错误，并保留设置页中的非敏感诊断信息。
- WebSocket 断开：停止继续写入，保留已安全提交的文本；下次会话重新建连。
- 当前没有文本焦点：不开始写入并提示用户先点击输入位置。
- 目标控件在会话中发生外部编辑：立即进入安全停止/最终复制模式，禁止覆盖用户输入。
- F5 松开后重复收到 final：由会话状态机去重，最终写入最多发生一次。

音频只在当前会话期间发送到腾讯云，不保存本地录音。文本日志默认关闭；开启后仅保存在用户本机，并可随时关闭或删除。日志中不写入 SecretId、SecretKey、签名 URL 或原始音频。

## 9. 测试与验收标准

自动测试使用假的 ASR 事件流和假的文本控件，不依赖真实腾讯凭证：

- 临时结果替换不会累积重复文本。
- final 会替换临时结果且只提交一次。
- 乱序、重复、延迟事件不会破坏文本状态。
- 焦点变化、外部编辑、AX 写入失败会进入安全回退。
- F5 默认注册、快捷键自定义、注册冲突和恢复旧值均可验证。
- 签名参数和敏感信息不会出现在日志中。

人工验收至少覆盖 TextEdit、备忘录、浏览器文本框和常用代码编辑器：

- 按住 F5 后能看到临时文字实时变化，松开后没有重复或残留。
- 中英文混说以及 `skill`、`Whisper`、软件/人名等专有词能正常返回，效果以实际一周体验为准。
- 快捷键改为其他组合后，原 F5 不再触发，新组合能触发。
- 网络失败、权限未授予和不支持的输入框均有明确提示，不会破坏已有文本。
- 连续使用一周后可以仅凭最终文本和状态日志判断是否值得继续做 Rime 集成。

## 10. 后续扩展，不进入本次实现

一周试用确认 ASR 效果后，再单独评估：把识别日志交给本地 Ollama 做批量总结、从修正记录生成热词、接入腾讯热词表或自学习模型，以及把最终文本写入 Rime/Squirrel 的词库和学习机制。上述扩展不反向增加当前 MVP 的依赖和运行链路。

## 11. 方案取舍

推荐原生 Swift 菜单栏应用。它能直接使用 macOS 的全局热键、音频、辅助功能和 Keychain API，打包成单一 `.app`，最适合做一周真实试用。

Python/PyObjC 脚本可以更快试通 WebSocket，但全局 keyUp、辅助功能文本范围维护和权限/打包体验更容易受运行环境影响。直接修改 Squirrel 则会把 ASR 网络、麦克风权限和输入法状态耦合在一起，无法快速判断“腾讯识别效果”本身，因此暂不采用。
