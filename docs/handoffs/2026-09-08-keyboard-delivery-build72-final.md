## 实施边界

- `AcknowledgedKeyboardWriter` 分开维护最新候选与已确认文字，一次只允许一笔实际写入。
- 等待期间合并候选，已发出的操作不重发；确认后才基于新状态计算下一次修改。
- `AXTextTarget` 在可读状态的键盘路径核对完整文档及选区，保留会话前已有内容。
- 改写分为选区准备、选区确认、替换输入、结果确认四步。可用时优先单次 AX 范围设置；键盘选择后也必须确认精确选区，未确认不得替换或删除。
- 保留原有 pacing，上屏确认异步进行，不用主线程睡眠等待编辑器。
- 超时仅用于结束无法确认的操作，不作为成功条件；焦点或文档变化仍触发停止，防止误写。
- ASR 错误收尾等待异步输入完成；取消不继续投递排队候选。
- 实际确认次数和深尾部改写指标在确认层统计，而不是把候选入队次数当作上屏次数。
- 其他应用原有 AX 路由保留；不可读目标的旧兼容路径并未在本任务中普遍重写。

## 交给诊断报告任务的新增要求

原交接文件 `2026-09-08-input-diagnostics-handoff.md` 继续有效。以下补充来自本轮已经实现的确认链路，不要求报告任务修改上屏策略。

| 需要呈现的信息 | 解释与注意事项 |
| --- | --- |
| 来源 App 路径、build、进程、会话 | 避免混用另一工作树或另一用户的日志；缺失标为未知 |
| ASR revision、segment 与操作关联 | 区分识别停了、候选仍增长、写入正在确认、后续候选被合并 |
| desired / submitted / acknowledged | 分别表示期望、已投递、已确认；不能把提交次数显示成成功次数 |
| `keyboard_selection_submitted` | 显示选择路线 `ax_range` 或 `keyboard`、预期范围 |
| `keyboard_selection_acknowledged` | 只有精确选区和原文匹配后才出现；成功 setter 不等于该事件 |
| `keyboard_replacement_submitted` | 替换文字或删除事件已经投递，不表示结果已完成 |
| `keyboard_write_submitted` | 追加路径的投递记录，与替换路径阶段统一呈现 |
| `keyboard_write_acknowledged` | 显示文档与选区均匹配，以及确认耗时 |
| `keyboard_write_unconfirmed` | 保留实际错误码，区分焦点变化、读取失败、确认超时、取消 |
| `keyboard_confirmed_state_changed` | 已确认后的文档或选区变化，不应混同“上一笔还没处理完” |
| 预期与实际选区、文字长度、匹配布尔值 | 可定位中间选择与不完整选区；不记录用户正文 |
| 操作投递、选区确认、结果确认时刻 | 用操作时间构建时序，不能用队列排空时刻代替发生时刻 |
| 每笔修改字符数、最大尾部、深改写次数 | pacing 与 immediate 路径口径一致；未知不能填 0 |
| 待确认、合并、取消和降级原因 | 待确认本身不是失败，也不能渲染成“已上屏” |
| 旧 `keyboard_caret_timeout` 的等待资格 | 旧日志可能 polls=0，并未实际等待；不要描述成等满150ms |
| 空框 AX 提示与控件角色 | 区分真实草稿、提示文字、不可读值和非文本控件 |
| 并发操作污染 | 用户或另一任务同时操作时，样本单独标记，不能计为有效回归 |

部分关联字段尚未实现，报告任务应标出缺失证据，不能根据事件顺序猜造操作 ID。继续遵守现有日志开关与隐私边界，不写入原始转写、草稿、剪贴板正文、音频、凭证或这些内容的哈希。
